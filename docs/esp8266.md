# ESP8266 (Xtensa LX106): draft

One LX106 core (`xtensa_lx7::Lx106`, the call0 profile of the Xtensa core) at 80 MHz, or 160 MHz
with CPU2X. Unmodified Arduino ESP8266 3.1.2 images (NONOS SDK 2.2.2) boot from a mask ROM
modelled in Rust, through eboot, into the SDK and `setup()`/`loop()`. Espressif publishes no ROM
ELF for this chip, so `--rom` is not used: the ROM's functions are entered by address
(`esp8266/src/rom`).

```sh
cargo build --release
./target/release/esp32sim --chip esp8266 --board esp12f --rom-strict \
    --flash-image ../fixtures/bin/esp8266-blink.bin --max-seconds 3
```

prints the ROM's banner and loader lines at its 74880 baud, eboot's, the SDK's start and the
sketch:

```
 ets Jan  8 2013,rst cause:1, boot mode:(3,6)

load 0x4010f000, len 3424, room 16
tail 0
chksum 0x2e
load 0x3fff20b8, len 40, room 8
tail 0
chksum 0x2b
csum 0x2b
v000420b0
~ld
rf cal sector: 1020
...
SDK ver: 2.2.2-dev(38a443e) compiled @ Jul  3 2019 15:53:05
phy ver: 1145_0, pp ver: 10.2

Ready
t=4 led=1
t=504 led=0
...
```

The flash image is the one `.bin` an Arduino build writes for offset 0: eboot at 0, the app at
0x1000 (`Soc::APP_OFFSET`). `--boot app`, `--bootloader`, `--ptable` and `--app` are refused.
`--rom-strict` stops the run at the first ROM function the model lacks, with its name and call
site; without it such a function returns 0 and logs once.

## Memory map

| Range | What |
| --- | --- |
| 0x3FF00000..0x3FF10000 | DPORT: NMI routing, edge-interrupt enables, CPU2X, the OTP words |
| 0x3FF20000..0x3FF40000 | WDEV: the microsecond counter, the TSF, the RNG, the MAC's timer 1 and interrupt status (interrupt 0); the MAC's queues are memory |
| 0x3FFE8000..0x40000000 | DRAM, 96 KB (the ROM's data and boot stack in the top 16 KB) |
| 0x40000000..0x40010000 | mask ROM: every pc is `rom::dispatch`'s; data reads are 0, logged once |
| 0x40100000..0x40110000 | IRAM, 64 KB, word access only |
| 0x40200000..0x40300000 | flash window, 1 MB at `Cache_Read_Enable`'s offset, word access only |
| 0x60000000..0x60001000 | peripherals (UART0 0x000, SPI1 0x100, SPI0 0x200, GPIO 0x300, timers 0x600, RTC 0x700, IO_MUX 0x800, WDT 0x900, UART1 0xF00) |
| 0x60001000..0x60002000 | RTC memory (the SDK's 768 bytes from 0x60001100); kept across every reset but power-on |
| 0x60002000..0x60100000 | the RF/PHY registers: memory |

A byte or halfword access to IRAM or the flash window is a LoadStoreError (EXCCAUSE 3); an
address outside the map is LoadProhibited/StoreProhibited (28/29).

## What is modelled

| | |
| --- | --- |
| CPU | LX106 call0 core, 15 interrupt lines plus the NMI, CCOUNT/CCOMPARE0, WAITI; CPU2X (DPORT 0x14 bit 0) doubles the core's clock against the 80 MHz APB clock, so a CCOUNT cycle is 6.25 ns of device time instead of 12.5 |
| UART0/1 | the shared `esp_periph::Uart`; receive raises interrupt 5; UART0 is the console, UART1 transmit-only |
| GPIO | GPIO0..15: output, enable, the W1TS/W1TC aliases, open drain (PINn bit 2), the interrupt types (rising, falling, either, low, high) into interrupt 4; pads at the chip's drive, else the host's level, else the IO_MUX pull-up, else their last level; GPIO16 through its RTC registers, with its pull-down |
| Strapping | GPIO15, GPIO0, GPIO2 read at a hardware reset's release (GPIO0 and GPIO2 pulled up, GPIO15 not; a reset releases the pads, so a floating GPIO15 reads low and floating means a flash boot); a jump to `_ResetVector` (`ESP.restart()`) keeps the boot mode latched before, as after a serial upload with GPIO0 low; the banner's `boot mode:(M,6)` and GPIO_IN bits 16 and up; `--strap` overrides |
| FRC1 | 23-bit down-counter, /1, /16, /256, auto-reload, edge or level; interrupt 9 with TEIE bit 1, or the NMI when DPORT 0x00 bit 0 routes it there (the Arduino core's waveform generator: `analogWrite`, `tone`, `Servo`) |
| FRC2 | 32-bit up-counter with its alarm into interrupt 10 (the SDK's `os_timer`) |
| Watchdog | the hardware WDT: two stages of 2^(16+n) APB cycles, fed with 0x73 (DPORT 0x18 bit 3, which the SDK keeps set, does not pause it); stage 0 raises interrupt 8, stage 1 resets with ROM cause 4. The SDK's soft watchdog runs on the MAC's timer 1 every 1.6 s and feeds it; with interrupts masked for about 8.4 s the chip resets |
| RTC | the software reset (0x700 bit 31, ROM cause 3), STORE0..3 and the other registers, the 150 kHz counter, the sleep timer and deep sleep |
| SPI0 | the flash commands the SDK sends directly (read, JEDEC id, status, program, erase), done at once |
| SPI1 (HSPI) | master transactions: command, address, MOSI and MISO phases, full duplex, bit order; a transaction goes to the host (`SocBus::spi_host`, `Hspi::host_wait`, `finish_spi_transfer`) or, without one, to the board (`BoardModel::spi_transfer`, host 1) |
| OTP | MAC0, MAC1, CHIPID and the fourth word encode the machine's whole MAC the way libmain decodes it (the OUI in the fourth word under CHIPID bit 12 with its CRC-8), so `WiFi.macAddress()` and `ESP.getChipId()` follow `--mac` |

### Reset causes

The ROM's banner prints its own numbering (`rtc_get_reset_reason`); the SDK derives the one
`ESP.getResetReason()` names from it and from the record it keeps in RTC STORE0 and RTC memory.
`SocBus::reset_cause` and `request_reset` use the ROM's (1 power-on, 2 external, 3 software, 4
hardware watchdog, 5 deep-sleep wake; another cause is taken as 2), and the CLI's reset line names
it (`EXT_RESET`, ...).

| What happened | ROM `rst cause` | `ESP.getResetReason()` | What the reset keeps |
| --- | --- | --- | --- |
| power-on | 1 | `Power On` | nothing |
| RST pin | 2 | `External System` | RTC memory |
| `ESP.restart()`, an exception, the soft watchdog (all jump to `_ResetVector`) | unchanged | `Software/System restart`, `Exception`, `Software Watchdog` | RTC registers and memory |
| hardware watchdog | 4 | `Hardware Watchdog` | RTC registers and memory |
| RTC software reset | 3 | the SDK's record | RTC registers and memory |
| deep-sleep timer, GPIO16 wired to RST | 5 | `Deep-Sleep Wake` | RTC memory |

"Unchanged" is why real boards print `rst cause:2` after `ESP.restart()` or a crash: the last
hardware reset was the programmer's auto-reset through RST. Sources and the SDK's derivation are
in `esp8266/src/rom/boot.rs`.

### Deep sleep

`ESP.deepSleep(us)` ends in the SDK writing the RTC sleep timer's target (0x704), its wake enable
(0x718 bit 3; 0 for `deepSleep(0)`), its power-down mask (0x740, all ones) and the sleep bit
(0x708 bit 20). The model then powers the digital domain down: the core waits with every
interrupt masked, FRC1, FRC2 and the watchdog stop, and the RTC drives GPIO16 (XPD_DCDC) high.
When the timer runs out (`SocBus::deep_sleep_until`), GPIO16 goes low for 100 us
(`periph::WAKE_PULSE_CYCLES`) and the chip sleeps on: on a board, GPIO16 wired to RST resets
it. The host does what that wire does, `request_reset(RST_EXT)`, which in deep sleep becomes
DEEPSLEEP_RESET; the SDK then finds its record in RTC memory and reports `Deep-Sleep Wake`.

## HLE ROM

`esp8266/src/rom/table.rs` holds every symbol of the core's `eagle.rom.addr.v6.ld` (348). About
130 have a model: the loader and banner (`boot.rs`), interrupts and exceptions (`_xtos_*`,
`ets_isr_*`, with real calls into the guest's handlers), the task scheduler (`ets_task`,
`ets_post`, `ets_run`, idle through WAITI), printing (`ets_printf` through the guest's putc1),
memory and string functions, integer and soft-float helpers, the flash API (`SPIRead` ...), the
crypto the SDK takes from the ROM (MD5, SHA-1 PRF, PBKDF2, RC4, AES), the PHY table and its I2C
registers, the GPIO helpers, `ets_delay_us` (a CCOUNT wait at the frequency the SDK announces),
`software_reset` and `rtc_get_reset_reason`. Concessions and their sources are listed in
[evidence/esp8266-boot](evidence/esp8266-boot/README.md).

## Model choices

- **The RTC clock is 150 kHz**, and the calibration register (GPIO 0x370) reads the value that
  tells the SDK so; its sleep times come out right on the modelled counter.
- **A jump to `_ResetVector` re-creates the digital peripherals**, though on the chip it resets
  nothing; the ROM and the SDK set them up again.
- **The ROM pulls up GPIO0 and GPIO2 at reset; a floating GPIO15 reads low.**
- **Deep sleep is told from the SDK's other sleeps by RTC 0x740 = all ones**, the mask only its
  deep-sleep path writes; the short sleeps of its start-up are not modelled (their wake-up status
  reads ready at once).
- **The RTC software reset is 0x700 bit 31**, as in the RTC block of the ESP32 that descends from
  this one; no ESP8266 source documents it and the SDK does not use it.
- **The GPIO16 wake pulse lasts 100 us.**
- **SPI1 without a host answers from the board**: the bare module reads 0xFF on MISO.

## Not modelled

- **Wi-Fi.** The SDK starts its MAC with no radio: `WiFi.begin` stays disconnected; no frame is
  sent or received.
- **Light sleep and modem sleep**, `ets_enter_sleep` and `rtc_enter_sleep` (the SDK in core 3.1.2
  programs the RTC itself and calls neither).
- **ADC (TOUT)**, I2S, SLC, SPI slave mode, the UART's autobaud and RTS/CTS: register memory.
- **IO_MUX functions and the pin swap (DPORT 0x28)**: GPIO_OUT drives a pad whatever its function;
  the pull-down bit of GPIO0..15 is not modelled.
- **The UART's bit timing**: a byte leaves at once; the ROM's 74880 baud and the sketch's 115200
  are the same to the host.
- **The flash's timing** and the cache: SPI0 commands take no time; the window maps without a
  `Cache_Read_Enable`.
- **The ROM's UART download mode**: a non-flash boot mode prints the banner and stops the run.
