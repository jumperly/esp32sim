# esp32sim (Jumperly fork)

- Upstream: https://github.com/mikroverk/esp32sim (the old `joakimeriksson/esp32sim` address opens the same repository)
- Fork: https://github.com/jumperly/esp32sim, a public GitHub fork of upstream. The previous private copy is `jumperly/esp32sim_old`; its history is this repository's `jumperly-legacy`.
- License: MIT (`LICENSE`, © 2026 Joakim Eriksson and Alice). The workspace has no third-party crates.
- The Jumperly monorepo pins branch `jumperly` as the `emulator/esp32sim` submodule.

## Branches

| Branch | What |
| --- | --- |
| `main` | A mirror of upstream's `main`; never gets our commits. `git fetch upstream && git push origin upstream/main:main` (a fast-forward). The push runs upstream's workflows on our Actions minutes, so sync when taking an update, not on every upstream commit. |
| `patch/<topic>` | One change, branched off `upstream/main`, written to upstream's rules (CONTRIBUTING.md, AGENTS.md: no fork markers, IDF citations, a receipt under `docs/evidence/<name>/` with a row in `docs/experiments.md`, the CPU comparison). Each is the branch of one upstream pull request, which the owner opens from the fork; the same branch is merged into `jumperly` through a fork pull request first. When upstream's `main` moves and the PR goes dirty, merge `upstream/main` into the branch (a merge commit, as upstream does; never rebase or force-push a published PR branch). |
| `patch/host-abi` | The fork-only work: the Jumperly host ABI (`wasm/src/jumperly.rs`, `wasm/src/net_host.rs`, `esp32s3/src/jumperly.rs`, `esp32c3/src/jumperly.rs`), the host bridges and taps, the queue transport, the LAN, the browser BLE, everything upstream would not take. Never goes upstream, so its places carry `Jumperly patch J<n>` comments. It is the old `jumperly-legacy` merged onto `jumperly`, with the parts the patch branches carry resolved to their upstream form. Since J28 the exports reach every chip through one trait, `JumperlyChip` (`wasm/src/chip.rs`), implemented in `wasm/src/chips/{s3,c3,esp32}.rs`: an export dispatches once (`MachineKind::chip_mut`) and a chip keeps the trait's defaults for what it lacks, so a new chip is one more impl, not one more branch in every export. |
| `jumperly` | The default branch: `upstream/main` plus `--no-ff` merges of the patch branches (fork pull requests #1–#4 for the first four) and of `patch/host-abi`. To take upstream, merge `upstream/main` into `jumperly` and resolve (the catalog `docs/experiments.md` conflicts every time: upstream's rows, then ours in order; a patch that upstream has merged resolves to upstream's text). Push `jumperly` and move the submodule pointer in the monorepo. Do not copy files back by hand. |
| `jumperly-legacy` | The branch before the split (2026-10-15, `33fb13a4`): upstream `017af524` with every J patch applied in place. Kept because older monorepo commits pin its SHAs. |

Base of `jumperly` at the split: upstream `9890ac55` (2026-10-15, "Merge pull request #234"). Rust 1.99.0 (`cargo +1.99.0`), ROMs from `tools/fetch-rom-elfs.sh roms` (`ESP32SIM_ROM_DIR=roms`).

The fork's ABI tests (`wasm/tests/jumperly.rs`) boot the Arduino sketches of the private `jumperly/fixtures`: from the monorepo's `emulator/fixtures` (the submodule checkout), or from `bin/` under `JUMPERLY_FIXTURES_DIR`; ROMs from `ESP32SIM_ROM_DIR` when it has the file, else `emulator/rom`. The fork's CI checks the fixtures out with a read-only deploy key of `jumperly/fixtures`, kept in this repository's `FIXTURES_DEPLOY_KEY` secret.
