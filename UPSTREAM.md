## Jumperly patches

Each patched place carries a `Jumperly patch J<n>` comment. To take newer upstream commits, on branch `jumperly`: `git fetch upstream` and `git merge upstream/main`, then resolve. Push `jumperly` and move the submodule pointer in the monorepo. Do not copy files back by hand.

| J3 | re-applied | `esp-soc/src/machine.rs` (`Console::raw`), `wasm/src/jumperly.rs`, `wasm/src/lib.rs` (`Emu::buf`), `wasm/tests/jumperly.rs` | Jumperly ABI: pin events, GPIO input, raw console per port, RMT frames |
| J3 | re-applied (reduced) | `esp-periph/src/uart.rs` (`Uart::rx_free`) | free RX FIFO space, so `esp32sim_uart_in` accepts only what fits. The RXFIFO_TOUT part of J3 is **dropped**: upstream now raises `INT_RXFIFO_TOUT` while the FIFO holds bytes (`refresh_rx_full`, test `short_message_raises_rx_timeout`), which is what the Arduino driver needs |
| J4 | re-applied (reduced) | `esp32s3/src/pwm.rs` (`PwmTap`), `esp32s3/src/bus.rs`, `esp32s3/src/soc.rs`, `esp-periph/src/ledc.rs`, `esp-periph/src/mcpwm.rs` (accessors), `wasm/src/jumperly.rs` | The LEDC / MCPWM **devices are now upstream's** (`esp_periph::Ledc`, `Mcpwm`); Jumperly's own register models (`pwm::Ledc`, `pwm::Mcpwm`, the `changes` queues) are **dropped**. What stays is the host tap: `PwmTap` compares every LEDC channel / MCPWM generator with its last report after a committing write (LEDC CHn_CONF0 / TIMERn_CONF with PARA_UP, any MCPWM or SYSTEM write; `pwm_commit` - the timer pause / reset writes in between are not shown) and queues a `PwmOut` (frequency + duty per matrix signal, cycle stamped; a reset reports running outputs as disabled). Upstream gained small accessors: `Ledc::channel_output` / `channel_idle_high`, `Mcpwm::channel_output` / `signal_base`; its `output()` keeps its behaviour. The accessors count a duty / compare value that PARA_UP or the shadow register has queued at once, not at the next timer overflow (upstream latches there, up to one PWM period later): the web simulator posts `tone()` in step with the sketch's Serial markers (`sim-runtime` buzzer tests). Hardware fades are not modelled upstream (the channel reports disabled) |
| J5 | re-applied (reduced) | `esp-periph/src/rtc_cntl.rs` (`adc_linear`, `linear_adc_code`), `esp32s3/src/soc.rs`, `wasm/src/jumperly.rs` | Upstream now models the S3 SENS one-shot ADC with host pad voltages (`AnalogInputs`, `RtcCntl::sens_adc`, kept across a chip reset); Jumperly's own SAR model (`SarAdc`, pad table, DONE / DATA registers) is **dropped**. What stays: the web simulator reads a potentiometer swept 0..3.3 V as 0..4095 (`analogRead`, `mcu-esp32` tests), and upstream's calibrated IDF curve gives 3.3 V -> 3802 and 1.55 V -> 1670 at 11 dB. So Jumperly mode sets `RtcCntl::adc_linear`, which swaps only the code function for a straight line to the attenuation's full scale (950 / 1250 / 1750 / 3100 mV, clamped to 4095, whole millivolts); the flag survives a chip reset. `esp32sim_adc_set` is a thin wrapper over `rtc.analog.set(gpio, Const(mv / 1000))` and still refuses outside Jumperly mode |
| J6 | re-applied | `esp-periph/src/i2c.rs`, `esp32s3/src/bus.rs`, `esp32s3/src/soc.rs`, `wasm/src/jumperly.rs` | I2C host bridge: with `defer`, TRANS_START is deferred (slice yield) and `esp32sim_bus_service` runs it, sending unknown addresses to the `host_i2c` import; turning the bridge off (`I2c::set_defer(false)`) runs a still-deferred transaction without the host (NACK). Merged with upstream's pin-aware devices: a device matches an address when it has no pins or its pins equal the route `set_pins` stored at TRANS_START (before the deferral), and the host owns only addresses no device answers |
| J7 | re-applied | `esp-periph/src/gpspi.rs`, `esp32s3/src/bus/dma.rs`, `esp32s3/src/bus.rs`, `wasm/src/jumperly.rs` | SPI2 host bridge: with `spi_host`, a transfer waits in `host_wait` (USR busy) until `esp32sim_bus_service` asks the `host_spi` import; turning the bridge off finishes a waiting transfer with MISO 0xFF. Upstream's per-transfer `spi2_pins` is dropped when the host takes the transfer; the board path (`spi_transfer_pins`) is unchanged |
| J8 | re-applied | `wasm/src/jumperly.rs`, `wasm/tests/jumperly.rs` | `esp32sim_reset`: the host restarts the chip (board RESET / EN) through the same `reboot` as a guest software reset (`chip reset` log line, cause POWERON); the cycle count keeps going |
| J9 | new | `esp32c3/src/jumperly.rs`, `esp32c3/src/{bus,soc,lib}.rs`, `wasm/src/{jumperly,machine}.rs`, `wasm/tests/jumperly.rs` | The Jumperly host ABI for the ESP32-C3: `jumperly_mode`, `pin_watch`, `pin_state` (S3 state-word layout, GPIO matrix signal 128 reported as `0x100`), `pin_events_take`, `gpio_set_input`, `uart_take`/`uart_in` (UART0..1 + USB-Serial/JTAG as port 3), `rmt_take`, `reset`; a pin change or an RMT frame ends the slice (`take_slice_yield`); a reset keeps the circuit's input levels. PWM, ADC and the I2C/SPI bridges stay S3 only (return unsupported on C3). The C3 mask ROM `esp32c3_rev3_rom.elf` is shipped in `emulator/rom` |

Conflicts resolved by hand in the last update: `esp-periph/src/{i2c,uart}.rs`, `esp-soc/src/machine.rs` (`Script` gained `uart0_seen` / `wait_mark`, `Console` keeps `raw`), `esp32s3/src/bus.rs` (upstream's `gpio_output_at` / `uart_pins` block runs first, then the J2 / J4 / J6 notes; constructor has both field sets), `esp32s3/src/bus/dma.rs`; `esp-periph/src/rtc_cntl.rs` is upstream's file as is. Auto-merged: `esp-soc/src/soc.rs`, `esp32s3/src/{lib,periph,soc}.rs`, `esp32s3/src/bus/tests.rs`, `esp32s3/tests/machine.rs`, `wasm/src/lib.rs`.

J1 covers the unmodelled scheduler (`run_unmodeled`, also with approximate CPI timing); the modelled and approximate-frontier schedulers are not patched - Jumperly never enables them.

The J4 tap is gated: it runs only in Jumperly mode (`esp32sim_jumperly_mode` sets `Console::raw`, `pin_watch`, `rmt_tap` and `pwm_tap`) or on the bus bridges (`esp32sim_bus_host` sets `I2c::defer`, `SocBus::i2c_host` and `SocBus::spi_host`). Upstream's LEDC, MCPWM and SENS ADC models run on every S3 run, as upstream intends.
